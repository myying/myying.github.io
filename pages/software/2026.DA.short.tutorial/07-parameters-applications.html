Parameter estimation

Everything so far has estimated state — a field, a storm's position. The same machinery can estimate parameters too, just by adding them to the state vector. This is Chapter 3's storm-tracking widget again, but now the storm's velocity is also unknown, estimated purely from how well each member's guess matches the observations over time.

Try it: members start with a rough, low guess for speed. Hit run and watch the drift-speed panel: the scattered member lines narrow and climb toward the true speed as evidence accumulates. Toggle estimation off mid-run to freeze it and see the difference.

Reading the panels

Storm track — member dots, ensemble mean, and the true track. The spread here comes entirely from members still disagreeing about velocity. Drift speed — each member's estimated speed as a thin line, narrowing toward the true speed (dashed) as evidence accumulates. Spread vs. rms error — the same honesty check as Chapters 3–4, for position.

This is the whole idea of state augmentation: any unknown quantity can ride along in the state vector and get estimated the same way as the state itself — model parameters, bias corrections, and more.

Suggested reading: Evensen et al., Data Assimilation Fundamentals (2022), Ch 19–23.
